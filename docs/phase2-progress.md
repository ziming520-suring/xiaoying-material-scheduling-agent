- Ruling: 技术写键由调度器为新调用分配，重试保留原键；业务 task/material 唯一性独立兜底 — 保证更换占用后能用新调用观察当前条件 — 编排器必须保存原请求供 unknown 恢复。

- Ruling: 本阶段沿用标准库，资料核查只做结构与引用检查，steps 是测试说明而非可执行 DSL — 不提前实现业务工具 — 语义和失败行为仍需第三阶段可执行测试证明。
- Ruling: 当前非 Git 目录，以阶段快照和证据保留版本，不创建或删除工作树 — 沿用第一阶段本地环境 — 最终交付仍需另行建立 GitHub 仓库与 commit SHA。
- Ruling: 历史审核依据保存在草稿内的不可变 ReviewBasis，而非只留哈希 — 解决当前资料升级后的可追溯问题 — 增加少量本地存储和返回字段，第三阶段须验证快照不能被模型篡改。
- Ruling: 新键保存同内容待确认稿仍执行当前前置条件检查；已成功原键重放保持历史语义 — 防止新调用将已冲突建议描述为再次保存成功 — 编排器必须区分历史回放与当前检查。
- Final review exclusions: 业务执行、迁移/权限运行、真实政策、模型配置与业务结果均未验证；基础代码只保留校验并回归。保持批准的阶段边界，不据此宣称完整考核达标。
