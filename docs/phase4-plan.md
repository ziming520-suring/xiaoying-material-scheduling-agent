## 任务 1：预算核算纠偏（先测试后实现）

- 新增 budget.py，bailian.py 继续导出 BudgetLedger 兼容旧调用；保留原 calls 全部行，通过原子事务登记策略版本 2。
- 原接口 reserve/record_usage/summary 不变。预留每次仍 100000 微元（0.10 元），总授权仍 10000000 微元（10 元）。有完整、合理 usage 的响应按输入 1 / 输出 3 元每百万 tokens 结算，高于当前官方 0.8 / 2；无 usage 或不合理 usage 的调用继续预留，不自动联网重试。
- 预算以整数微元累计：已结算保守费用 + 未结算预留 + 下次预留 <= 10 元。保留旧记录；不同 usage 不得覆盖已结算行；不修改模型、请求字节或输出上限。
- RED：旧账本保留、并发余额、已知用量结算、未知失败不释放、坏 usage/冲突结算阻止、未来策略拒绝。GREEN 后只升级真实账本一次，并保留迁移前后非敏感摘要。
- Ruling：10 元是用户授权金额上限，100 次只是此前内部保守预留算法。本次改善算法不增加授权金额，不删除或重置旧账本。代价：价格变更需重新核查；账本估算仍非平台账单。
