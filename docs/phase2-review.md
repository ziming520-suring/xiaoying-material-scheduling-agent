# 第二阶段独立设计审查与修正

审查者：独立 AI 审查代理；只读审查业务契约、合成资料、验收映射和静态核查脚本。没有执行业务场景，也不是人工评审。初次结论为 With fixes：无 Critical、两项 Important、无额外 Minor。

## 1. 固定版本断言限制了合法模型动作

原设计问题：S05/S11/S16 使用 version=1→2，隐含模型在一次运行内只能保存一次建议。反例：第一次运行保存 S19，再合法改为 S20；第二次恢复原 S18，最终版本为 3，仍满足规则，却会被原断言误判。

已修正：S05 绑定实际待确认版本 v，确认后 v+1；S11 绑定前次实际版本，逐个有效变更递增且保持同一稿；S16 绑定改建议前 v，一次明确更新后 v+1，旧确认被拒且不增版本。确认时段从实际建议取值，不从预设常量取值。

主执行者核对：在上述反例中，新断言接受合法的 1→2→3；去重增版本、拒绝后增版本、旧确认接受新建议仍应失败。此为设计反例推演，未冒充业务测试。修正后静态核查仍通过，全部 execution_status 保持 not_run。

## 2. 摘要引用不足以恢复历史审核依据

原设计问题：如果当前资料与规则更新，旧 material_ref/check_ref 不能还原原文与来源；正常通过时 findings 为空，无法仅凭草稿证明保存依据。

已修正：Draft 新增 review_basis，包含原始素材、全部补充资料、完整规则、有效读取结果、来源版本/provenance、检查结果和检查逻辑时间。保存事务内从可信数据生成，模型不能提交。已确认草稿及快照不随当前资料更新；drafts 查询完整返回快照。待确认更新生成新版本，去重不重写旧快照。

主执行者核对：以 M01 保存后原文和规则升版为反例，旧 Draft.review_basis 仍提供旧文本/授权/规则，可重建 refs；当前引用过期仍阻止新的保存或确认。具体持久化与运行正确性留待第三阶段历史依据测试验证。
